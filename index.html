    Pass-the-Bomb game

    1. What hashing is trying to do

    A hash function takes an input — usually a string — and turns it into a small, fixed-range number using arithmetic on the characters. Every exam-spec hash function follows the same shape: sum something (usually the ASCII value of each character, sometimes weighted by position), then reduce it with a modulus.

    Core principle: a hash function is not "clever" — it is arithmetic you can trace by hand, character by character. Get the loop, the weights and the modulus exactly right, and checksums, hash tables and collision handling all follow the same underlying shape.

    Sum

    Combine each character's value — usually ord(ch) — sometimes multiplied by a position weight.

    Reduce

    Apply % n to compress the sum into a fixed range, from 0 up to n-1.

    Map

    Use the reduced value as a table index, or as a checksum digit/letter appended to the original data.

    Match the spec

    Exam questions define the exact weights and modulus to use. Never substitute a formula from a previous question.

    Two recurring exam applications sit on top of this same arithmetic:

    1 Checksums→catch a mistyped ISBN or NRIC using one extra digit/letter
    2 Hash tables→turn a search into a near-instant lookup by computing where an item should live

    2. Building a hash function

    The most common starting point weights each character by its position, using ord() to convert a character to its ASCII value:

    def hash(string) — weighted by position

    def hash(string):
    total = 0
    for i in range(len(string)):
        total += ord(string[i]) * (i+1)
    return total

hash('abcde') % 10

    Looping style: index vs character

    LoopWhat i isWhen to use it
    for i in range(len(s)):an index (0, 1, 2, …)you need the position, e.g. to weight it or to write s[i]
    for ch in s:the character itselfyou only need the letters, not their position
    for i, ch in enumerate(s):both, togetheryou need the position and the character at the same time
    The mistake that keeps recurring: writing for i in string and then treating i like a position — e.g. string[i] or (i+1). This fails because i is the character, not an index. Fix: loop with range(len(string)) when you need position, or use enumerate(string) to get both together.

    Why the modulo is there

    % n compresses a large, unbounded sum into a fixed range (say, 0–9 or 0–12). This prevents overflow and makes the result directly usable as a table index or a single checksum digit.

    4. Checksum systems — ISBN-10

    Every published book carries an International Standard Book Number. The first 9 digits identify the book; a 10th check digit is calculated from them using a weighted-modulus scheme, so that a single mistyped digit can be detected.

    The algorithm

    1. Multiply each of the 9 digits by a fixed weight: 10, 9, 8, 7, 6, 5, 4, 3, 2 respectively.
    2. Add the 9 products together to get a total.
    3. Divide the total by 11 and take the remainder.
    4. The check digit is (11 − remainder) % 11.
    Special case: if the calculated check digit is 10, it is written as the character 'X' instead of a two-digit number.

    Worked example for 075154926:

    0×10 + 7×9 + 5×8 + 1×7 + 5×6 + 4×5 + 9×4 + 2×3 + 6×2 = 214

    214 ÷ 11 = 19 remainder 5  →  check digit = (11 − 5) % 11 = 6

    Complete ISBN: 0751549266

    def isbn(string)

    def isbn(string):
    count = 0
    mult = [10, 9, 8, 7, 6, 5, 4, 3, 2]

    for i in range(len(string)):
        count += int(string[i]) * int(mult[i])

    count = 11 - count
    n = round(count % 11)
    if n == 10:
        return string + 'X'
    else:
        return string + str(n)

    0340850450340850450
    Summary: weight the 9 digits with [10..2], sum the products, take the remainder mod 11, then compute (11 − remainder) % 11 — substituting 'X' if that check digit equals 10.

    6. Hash tables without collision handling

    A hash table turns a linear search into a near-instant lookup: compute an index from the item, store the item there, and search by recomputing the same index.

    Basic table: init_table / hashtable / search

    def hash(string):
    total = 0
    for i in range(len(string)):
        total += ord(string[i]) * (i+1)
    return total

def init_table(n):
    return [''] * n

def hashtable(seq):
    n = len(seq)
    table = init_table(n)
    for item in seq:
        val = hash(item) % n
        if table[val] == '':
            table[val] = item
    return table

data = ['cdab', 'dbac', 'adcb', 'acbd', 'abcd']
data_table = hashtable(data)

def search(table, item):
    n = len(table)
    val = hash(item) % n
    if table[val] == item:
        return True
    else:
        return False

search(data_table, 'bdca')

    7. Collision handling — separate chaining

    When two items hash to the same index, separate chaining stores more than one item per slot: a slot starts empty, becomes a single string on its first item, then becomes a list once a second item collides into it.

    hashtable() / search() with chaining

    def hashtable(seq):
    n = len(seq)
    table = init_table(n)
    for i in range(len(seq)):
        index = hash(seq[i]) % n
        if table[index] == '':
            table[index] = seq[i]
        elif type(table[index]) == str:
            table[index] = [table[index], seq[i]]
        else:
            table[index].append(seq[i])
    return table

def search(table, item):
    index = hash(item) % len(table)
    if table[index] == '':
        return False
    return item in table[index]

data = ['cdab','dbac','dabc','bdac','badc']
data_table = hashtable(data)
search(data_table, 'cdab')
    MistakeFix
    Appending to a string: calling .append() on the first item stored as a plain string raises AttributeErrorStrings are immutable and have no .append() — convert the slot to a list on the first collision.
    Mixing slot types inconsistently (some string, some list)Pick one convention: empty → '', first item → string, second item → convert to list, third+ → append.
    Confusing for item in seq with for i in range(len(seq))item is already the element — don't re-index it with hash(seq[item]).
    Why item in table[index] works either way: Python's in operator checks list membership and string substring containment — so the same line searches correctly whether the slot holds one string or a list of strings.
    Cleanest design: initialise every slot as ''. On the first insert, replace it directly with the item (as a string). On a collision, convert to a list and append. Alternatively, start every slot as a list from the beginning, to avoid the type-juggling entirely.

    8. Exam-spec chaining — 2018 YIJC Promo (no in)

    Task 3.3 & 3.4 supply the hash function and ask for hash_table(seq) using separate chaining, plus a search(item) that returns True/False — with one added constraint:

    Given hash(), plus hash_table() / search() without `in`

    def hash(string):
   result = 0
   for i in string:

    9. Collision handling — linear probing

    Linear probing keeps one item per slot, but on a collision it scans forward — wrapping around to the front of the table — until it finds an empty slot. A small warm-up function isolates just the wrap-around traversal pattern:

    def browse(array, n) — the wrap-around pattern

    def browse(array, n):
    num = len(array)

    # Phase 1: from n to end
    for i in range(n, num):
        print(array[i])

    # Phase 2: from 0 to n-1
    for i in range(0, n):
        print(array[i])

lst = ['a', 'e', 'i', 'o', 'u']
browse(lst, 2)   # output: 'i' -> 'o' -> 'u' -> 'a' -> 'e'
    MistakeFix
    Nested while count < num loops caused repeated printingTwo clean for loops — one per phase — are enough.
    Variable shadowing: reusing i inside a nested loopGive nested loops distinct variable names.
    Assumed range(n, num+1) was neededrange() already excludes its end, and the array's last valid index is num-1 — the two "off-by-ones" cancel out.

    The same wrap-around pattern drives both insertion and search:

    hashtable() / search() with linear probing

    def hashtable(seq):
    tbl = init_table(len(seq))
    for item in seq:                     # Loop 1: go through each item
        num = len(tbl)
        index = hash(item) % num

        # Loop 2: Phase 1, from index -> end
        for i in range(index, num):
            if tbl[i] == '':
                tbl[i] = item

        # Loop 3: Phase 2, from 0 -> index-1
        for i in range(0, index):
            if tbl[i] == '':
                tbl[i] = item
    return tbl

def search(table, item):
    num = len(table)
    index = hash(item) % num

    # Phase 1: from index to end
    for i in range(index, num):
        if table[i] == '':
            return False
        if table[i] == item:
            return True

    # Phase 2: from 0 to index-1
    for i in range(0, index):
        if table[i] == '':
            return False
        if table[i] == item:
            return True

    return False

data = ['cdab','dbac','dabc','bdac','badc']
data_table = hashtable(data)
search(data_table, 'bcda')
    How to read it: compute the starting index, then scan forward to the end of the table (Phase 1), then wrap around and scan from the front up to that starting index (Phase 2). Insert — or match — at the first empty slot or exact match. Stop scanning the moment an empty slot appears: that proves the item cannot be any further along the probe sequence.

    10. Recurring exam lessons

    ISBN vs NRIC

    Both are weighted-sum-then-modulo checksums, but ISBN uses weights [10..2] mod 11 with a special 'X' case; NRIC uses weights [2,7,6,5,4,3,2] mod 11 mapped through a letter table.

    Hash functions are problem-specific

    Always implement exactly what the question defines — weighted or plain ASCII sum — don't reuse a previous question's formula.

    Hash table basics

    Initialise every slot as ''; compute index = hash(item) % n; resolve collisions exactly as the question specifies — skip, chain, or probe.

    Search logic

    Hash the whole item once — don't loop over its characters again inside search.

    Exam questions reward precision: stick to the given specification, don't add extra weighting, don't use a forbidden built-in, and don't reduce modulo twice.

    11. Before-the-exam checklist

    • Did I use range(len(x)) when I need the index, and for ch in x / enumerate(x) when I need the character?
    • Did I use % (modulo), not / (division), wherever the question asks for a remainder?
    • Does my weights list length match the number of characters I'm actually looping over — after stripping any prefix letter?
    • Does my table size match the modulus used inside hash() — e.g. 13 slots for % 13?
    • Am I indexing with the computed hash value, not the loop counter?
    • Have I handled the collision case exactly as specified — skip, chain, or probe — not just the method I personally prefer?
    • Have I checked special-case outputs — check digit 10 → 'X', and that a letter-mapping table has no duplicates or gaps?
    • If the question forbids a built-in (like in), have I actually avoided it everywhere, including inside loops?
    Red flag: if your code works on the sample data but you can't explain, by hand, why the modulo or the loop range is correct, it will fail the exam's second test case.
